  - @repository

## Reliability And Performance

### RULE: JAVA-PERF-701
severity: WARN
scope: performance
intent: 循环中不得执行无边界的远程 HTTP、RPC 或 client 调用，除非具备批处理、超时和并发控制。

detect:
  semantic: loop body performs remote HTTP/RPC/client call without batching, concurrency control, timeout, or rate limiting
fix: 请将远程工作批处理化，统一收敛到 service/client 抽象，并增加超时、重试和限流保护。
prompt:
  violation: 检测到循环中疑似存在缺少边界控制的远程调用。
  requirement: 循环中的远程调用必须有边界、可观测、受超时保护，并优先使用批处理。
  solution: 请将循环重构为批处理或受控并发，并在 client 层落实超时/重试策略。
context:
  - @service
  - @client

### RULE: JAVA-ERR-602
severity: WARN
scope: error
intent: Service 与 API 错误处理中必须区分业务异常与系统/基础设施异常。

detect:
  semantic: business exceptions and system/infrastructure exceptions are collapsed into a generic runtime exception or generic API error
fix: 请引入明确的业务异常类型或错误码，单独转换基础设施异常，并对外返回脱敏后的稳定错误响应。
prompt:
  violation: 检测到错误处理可能将业务失败与系统失败混成通用异常或通用响应。
  requirement: 业务规则失败、校验失败和基础设施失败必须分开表达和处理。
  solution: 请拆分异常类或错误码，并更新全局处理器以返回稳定且脱敏的 API 错误。
context:
  - @exception
  - @advice
  - @service

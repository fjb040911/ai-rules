### RULE: ARCH-101
severity: FATAL
scope: architecture
intent: 业务层与领域层禁止直接调用平台相关接口。

detect:
  import: "platform/**"
  where: importer in @src/(app|domain)/**
fix: 请通过 adapter 层封装平台能力并在上层引用抽象接口。
prompt:
  violation: 检测到上层模块直接依赖平台实现。
  requirement: 平台能力必须通过适配层隔离。
  solution: 请引入 adapter 抽象并替换直接调用。
context:
  - @adapter

severity: FATAL
scope: concurrency
intent: 共享可变状态访问必须有同步策略。

detect:
  semantic: shared mutable state accessed without synchronization
fix: 请使用 mutex/atomic 或无锁安全结构保护共享状态。
prompt:
  violation: 检测到共享可变状态无同步访问。
  requirement: 并发读写必须满足线程安全。

  - @common

scope: concurrency

  semantic: blocking I/O inside lock scope

prompt:
  violation: 检测到锁内阻塞 I/O 操作。
  requirement: 临界区应最小化并避免长时阻塞。
  solution: 重构临界区边界并降低锁竞争。
context:
  - @common

### RULE: CONC-303
severity: WARN
scope: concurrency
intent: 同一份共享状态在相关代码路径中必须遵循一致的锁或 atomic 协议。

detect:
  semantic: shared state follows inconsistent lock or atomic protocol across code paths
fix: 请统一同步策略，确保同一状态始终由同一把锁、同一守卫或同一 atomic 契约保护。
prompt:
  violation: 检测到共享状态周围的同步纪律不一致。
  requirement: 共享可变状态在所有入口路径上都必须遵循明确且一致的并发协议。
  solution: 统一锁所有权和 atomic 规则，并验证所有读写路径遵循同一协议。
context:
  - @common

### RULE: CONC-304
severity: FATAL
scope: concurrency
intent: 相关路径必须以一致顺序获取共享锁，并避免跨回调/跨线程的死锁协议。

detect:
  semantic: related paths acquire shared locks in inconsistent order or can deadlock across callbacks workers or interrupts
fix: 定义统一锁顺序约定，让回调或中断路径保持最小化，并移除环形等待机会。
prompt:
  violation: 检测到疑似不一致的锁顺序或容易死锁的同步路径。
  requirement: 并发路径必须遵循显式且一致的锁顺序与回调同步策略。
  solution: 统一锁顺序、减少嵌套持锁范围，并将回调/中断处理从不安全等待路径中分离。
context:
  - @src
  - @common

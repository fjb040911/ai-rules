# AI-RULES electron

version: 0.1.0
stack: electron

### RULE: ARCH-101
severity: FATAL
scope: ui
intent: UI 组件不得直接发起请求。

detect:
  ast: frontend/no-direct-network-call
  where: filePath in @uiEntry/**
fix: 将请求逻辑下沉到 service 层，并在组件中调用 service。
prompt:
  violation: 检测到 UI 层直接发起网络请求。
  requirement: UI 组件禁止包含请求逻辑。
  solution: 请将请求迁移到 service 层并复用现有 API 客户端。
context:
  - @apiClient
  - @services

### RULE: ARCH-102
severity: FATAL
scope: ui
intent: UI 组件不得直接访问存储层或数据库。

detect:
  regex: "(prisma|typeorm|mongoose|sequelize)"
  where: filePath in @uiEntry/**
fix: 将数据访问移动到 server/service 层，再通过 API 调用。
prompt:
  violation: 检测到 UI 层出现数据层/数据库访问。
  requirement: UI 层不得依赖数据库或 ORM。
  solution: 请通过服务层与 API 边界完成数据访问。
context:
  - @services

### RULE: ARCH-103
severity: WARN
scope: module
intent: 禁止跨层级逆向依赖（ui -> service -> data）。

detect:
  import: @data/**
  where: importer in @components/**
fix: 通过 service 层封装后暴露给 UI。
prompt:
  violation: 检测到跨层级逆向依赖。
  requirement: 依赖方向必须遵循分层架构。
  solution: 请重构依赖边界并通过 service 层暴露能力。
context:
  - @services
  - @data

## Security

### RULE: FE-SEC-101
severity: FATAL
scope: security
intent: 禁止通过 innerHTML 或 dangerouslySetInnerHTML 直接注入不可信内容。

detect:
  ast: frontend/no-raw-html-injection
  where: filePath in @src/**/*.{ts,tsx,js,jsx,vue}
fix: 移除原始 HTML 注入，或在渲染前通过可信的统一消毒层进行严格清洗。
prompt:
  violation: 检测到前端代码使用原始 HTML 注入 API。
  requirement: 用户可控内容未经严格清洗前不得以原始 HTML 形式渲染。
  solution: 请改为安全渲染方式，或接入统一的 HTML 清洗工具。
context:
  - @components
  - @sanitize

### RULE: FE-SEC-102
severity: FATAL
scope: security
intent: 禁止通过 eval 或 Function 构造器动态执行前端代码。

detect:
  ast: frontend/no-dynamic-code-exec
  where: filePath in @src/**/*.{ts,tsx,js,jsx,vue}
fix: 请使用显式逻辑、映射表或经过验证的解析方案替代动态执行。
prompt:
  violation: 检测到前端代码中存在动态代码执行。
  requirement: 前端代码不得将任意字符串当作代码执行。
  solution: 请将动态执行逻辑重构为显式且安全的控制流。
context:
  - @utils

### RULE: FE-SEC-103
severity: WARN
scope: security
intent: 禁止在前端源码中硬编码 secret、token、password 或 API key。

detect:
  regex: "(api[_-]?key|secret|token|password)\\s*[:=]\\s*[\"'][A-Za-z0-9_\\-]{8,}[\"']"
  where: filePath in @src/**/*.{ts,tsx,js,jsx,vue}
fix: 将敏感值迁移到后端托管配置或安全的环境注入机制中。
prompt:
  violation: 检测到前端代码中疑似硬编码的敏感凭据。
  requirement: 敏感凭据不得出现在前端源码文件中。
  solution: 请移除硬编码值，并改为安全配置流转方案。
context:
  - .env.example
  - @config

### RULE: FE-SEC-104
severity: FATAL
scope: security
intent: 用户可控的 HTML、Markdown 或动态 URL 内容，未经可信清洗或编码，不得流入 DOM 渲染危险点。

detect:
  semantic: user-controlled rich text, html fragments, markdown output, or dynamic URLs reach DOM rendering sinks without centralized sanitization or trusted encoding
fix: 请在内容进入 DOM sink 之前，统一经过可信的清洗层或安全渲染抽象。
prompt:
  violation: 检测到疑似 XSS 风险，存在不可信内容未经可信清洗直接流入 DOM 渲染的情况。
  requirement: 不可信富文本和动态 URL 必须经过清洗、编码，或通过受控的安全渲染方式处理。
  solution: 请引入统一可信的清洗边界，或改用更安全的渲染原语。
context:
  - @sanitize
  - @components

### RULE: FE-SEC-105
severity: WARN
scope: security
intent: HTML 入口中引用的第三方脚本在可行时应配置 Subresource Integrity (SRI)。

detect:
  regex: "<script(?![^>]*\\bintegrity=)(?=[^>]*\\bsrc=)[^>]*\\bsrc\\s*=\\s*[\"']https?://"
  where: filePath in **/*.html
fix: 请为第三方脚本补充 integrity 和 crossorigin，或通过可信构建流程自托管并固定版本。
prompt:
  violation: 检测到第三方 script 标签缺少完整性保护。
  requirement: 远程脚本引用应使用 SRI，或采用等价的可信资产交付方式。
  solution: 请增加 SRI 元数据与跨域配置，或将依赖迁移到本地可信构建链路中。
context:
  - @public
  - index.html

## Style

### RULE: STYLE-501
severity: INFO
scope: style
intent: 组件命名使用 PascalCase，文件命名与组件一致。

detect:
  regex: "export default function [a-z]"
fix: 组件命名改为 PascalCase，并与文件名保持一致。
prompt:
  violation: 检测到组件命名不符合约定。
  requirement: 组件与文件命名应遵循统一规范。
  solution: 请统一为 PascalCase 并调整文件名。
context:
  - @components

### RULE: STYLE-502
severity: INFO
scope: style
intent: 禁止在组件内定义过大内联函数。

detect:
  ast: ArrowFunctionExpression[body.statements>30]
  where: filePath in @components/**
fix: 提取为独立函数或自定义 hook。
prompt:
  violation: 检测到过大的内联函数。
  requirement: 组件应保持精简并提升可维护性。
  solution: 请将复杂逻辑抽离到 hook 或 utils。
context:
  - @hooks
  - @utils

### RULE: ELEC-301
severity: FATAL
scope: security
intent: 渲染进程代码不得直接导入高权限 Node.js 内置模块。

detect:
  regex: "(from ['\"](fs|path|child_process|os|net|tls|crypto)['\"]|require\\(['\"](fs|path|child_process|os|net|tls|crypto)['\"]\\))"
  where: filePath in @renderer/**/*.{js,jsx,ts,tsx}
fix: 将高权限能力移动到 preload 或 main-process 服务中，并只向渲染进程暴露最小桥接接口。
prompt:
  violation: 渲染进程代码直接导入了 fs、child_process、net 等高权限 Node 内置模块。
  requirement: Electron 渲染进程必须与高权限 Node API 隔离。
  solution: 把高权限能力移动到 preload 或 main，并通过安全桥接仅暴露最小方法面。
context:
  - @preload
  - @services

### RULE: ELEC-302
severity: WARN
scope: security
intent: 渲染进程不应直接导入 electron 包来访问 IPC 或 shell 能力。

detect:
  regex: "(from ['\"]electron['\"]|require\\(['\"]electron['\"]\\))"
  where: filePath in @renderer/**/*.{js,jsx,ts,tsx}
fix: 将渲染侧 IPC 使用封装到 preload 暴露的 service 中，而不是直接导入 electron。
prompt:
  violation: 渲染进程代码直接导入了 electron 包。
  requirement: 渲染进程应通过窄化的 preload bridge 使用能力，而不是直接拿 electron API。
  solution: 用 preload 中定义的 bridge 方法和类型化 service helper 替代直接 electron 导入。
context:
  - @preload
  - @renderer

### RULE: ELEC-303
severity: WARN
scope: security
intent: preload 应暴露窄化、类型化的 bridge，而不是把原始高权限能力直接挂到 window。

detect:
  semantic: preload exposes raw ipcRenderer, shell, or unrestricted node capabilities directly to window instead of a narrow typed bridge
fix: 仅通过 contextBridge 暴露最小必要方法，并将原始高权限对象保留在 preload 内部。
prompt:
  violation: preload 看起来把原始高权限能力直接暴露给了 window。
  requirement: preload 只能向渲染进程暴露经过审查的最小 bridge 面。
  solution: 用最小类型化 bridge 方法替代宽泛的原始能力暴露，并补上严格输入校验。
context:
  - @preload
  - @mainProcess

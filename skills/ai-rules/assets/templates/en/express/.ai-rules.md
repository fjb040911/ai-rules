# AI-RULES express

version: 0.1.0
stack: express

### RULE: NODE-ARCH-101
severity: FATAL
scope: transport
intent: Transport-facing Node.js modules must not import repositories or raw data clients directly.

detect:
  import: @repositories/**
  where: importer in @transport/**
fix: Move persistence access into service modules and let transport layers depend on services instead of repositories.
prompt:
  violation: A transport-facing Node.js module imports repositories or raw data clients directly.
  requirement: Routes, controllers, and handlers must delegate persistence access through services.
  solution: Move the data access logic into a service and inject or import that service from the transport layer.
context:
  - @services
  - @repositories

### RULE: NODE-ARCH-102
severity: WARN
scope: transport
intent: Transport handlers should stay thin and avoid mixing validation, orchestration, persistence, and response shaping in one function.

detect:
  semantic: request or message handlers contain orchestration, validation, persistence, and response formatting in the same function instead of delegating to service modules
fix: Split request wiring from business orchestration and move reusable logic into service modules.
prompt:
  violation: A transport handler appears to mix too many responsibilities inline.
  requirement: Transport code should stay thin and delegate business orchestration to services.
  solution: Extract validation, orchestration, and persistence logic into services and keep the handler focused on transport concerns.
context:
  - @transport
  - @services

## Reliability And Security

### RULE: NODE-ERR-201
severity: WARN
scope: reliability
intent: Async handlers should propagate errors into centralized error handling instead of swallowing them locally.

detect:
  semantic: async handlers catch errors, log them, or ignore them without forwarding to centralized error handling
fix: Forward errors to centralized middleware or framework error boundaries and avoid empty or log-only catch blocks.
prompt:
  violation: An async Node.js handler appears to swallow or locally bury errors.
  requirement: Async handlers must propagate failures into centralized error handling.
  solution: Re-throw, return next(error), or delegate to framework error boundaries instead of swallowing the failure.
context:
  - @middleware
  - @transport

### RULE: NODE-SEC-202
severity: FATAL
scope: security
intent: Sensitive credentials and tokens must not be logged from Node.js services.

detect:
  regex: "(console\\.(log|error|warn)|logger\\.(info|warn|error|debug)).*(password|token|secret|authorization|cookie)"
  where: filePath in @src/**/*.{js,ts}
fix: Remove or redact sensitive values before logging and centralize safe logging helpers.
prompt:
  violation: A logging statement appears to expose credentials or security-sensitive values.
  requirement: Logs must not leak passwords, tokens, cookies, or authorization data.
  solution: Redact or remove sensitive fields and use safe structured logging helpers instead.
context:
  - @config
  - .env.example

### RULE: NODE-PERF-301
severity: WARN
scope: reliability
intent: Outbound network calls should use explicit timeouts, abort signals, or bounded retry behavior.

detect:
  semantic: outbound HTTP or RPC calls are created without explicit timeout, abort signal, or bounded retry policy
fix: Introduce timeout, abort, and bounded retry controls for outbound HTTP/RPC clients.
prompt:
  violation: An outbound Node.js network path appears to lack timeout or bounded retry controls.
  requirement: External calls must have explicit failure bounds so they cannot hang indefinitely.
  solution: Add timeout/abort controls and keep retries bounded and observable.
context:
  - @services
  - @config

### RULE: EXPRESS-301
severity: WARN
scope: transport
intent: Express route handlers should stay thin and delegate business workflows to services.

detect:
  semantic: express route handlers contain business branching, persistence logic, and response formatting inline instead of delegating to services and middleware
fix: Move orchestration and business branching out of route callbacks into services and middleware.
prompt:
  violation: An Express route handler appears to contain heavy workflow logic inline.
  requirement: Route handlers should focus on request wiring and delegate business workflows.
  solution: Extract the heavy route logic into services and keep middleware/handlers transport-focused.
context:
  - @routes
  - @services

### RULE: EXPRESS-302
severity: WARN
scope: reliability
intent: Express handlers should not send a response and continue control flow without an explicit return or error transfer.

detect:
  semantic: express handlers send a response and continue control flow without return or next(error), creating double-send or hidden fallthrough risk
fix: Make response termination explicit and avoid fallthrough after res.send/res.json/res.end or next(error).
prompt:
  violation: An Express handler appears to risk double-send or hidden fallthrough after responding.
  requirement: Response termination must be explicit so handlers do not continue unexpectedly.
  solution: Add explicit returns or restructure the control flow so no code path continues after the response is finalized.
context:
  - @routes
  - @middleware
